# Skill 设计模式库

从成熟 Studios 系统中提炼的五种 Skill 设计模式。创建新 Skill 时参考这些模式，选择最合适的作为骨架。这些模式不互斥——一个 Skill 可能同时体现多种模式。

---

## 模式一：策略-执行分离

**描述**：将策略规划与具体执行分为两个 Skill。策略 Skill 定义方向、框架、标准；执行 Skill 按照策略实施具体动作。

**适用场景**：
- 某项工作既有"定方向"的需求，又有"做具体事"的需求
- 策略部分需要高层思考，执行部分需要细节操作
- 单个 Skill 过于庞大，需要拆分以保持聚焦

**frontmatter 特征**：

| | 策略 Skill | 执行 Skill |
|---|-----------|-----------|
| outputs | 框架文档、策略文档 | 具体交付物 |
| duration | 较长 | 较短 |
| agents | 高层级 | 执行层级 |

**body 结构特征**：
- 策略 Skill：含策略框架章节（决策矩阵）、与执行 Skill 的协作说明、对执行输出的质量要求
- 执行 Skill：在必备上下文引用策略 Skill 的输出、按策略标准执行、含输出质量自检清单

---

## 模式二：简报-方案-复盘闭环

**描述**：从 Brief 出发，经过方案制定、执行、到复盘的完整业务闭环。每个阶段对应一个 Skill，数据在各阶段之间流转。

**适用场景**：
- 有明确起止时间的项目型工作
- 需要从需求到交付到复盘的完整链路

**数据流**：Brief（简报）→ Plan（方案）→ Execute（执行）→ Review（审核）→ Debrief（复盘）

**body 结构特征**：
- 必须包含前置条件检查（上游输出是否完整）
- 必须包含与上下游 Skill 的协作表
- inputs 必须包含上游 Skill 的 outputs

---

## 模式三：平台-内容-运营三角

**描述**：将平台配置、内容生产、运营策略三者分离为独立 Skill，通过数据流关联。

**适用场景**：
- 多平台/多渠道运营
- 各平台有不同的规范和内容要求

**三角关系**：内容日历（策略）↔ 平台运营 Skill ↔ 内容生产 Skill

**body 结构特征**：
- 必须包含平台/渠道特有规范
- 必须包含内容审核流程
- 必须声明与其他平台/渠道 Skill 的关系

---

## 模式四：审计-迭代模式

**描述**：先对现状进行全面诊断（审计），再基于诊断结果制定改进方案，执行后再次评估，形成迭代循环。

**适用场景**：
- 需要基于现状做判断的工作
- 有持续改进需求的工作

**循环结构**：审计（当前状态评分 + 问题清单）→ 方案（基于审计的策略）→ 执行 → 评估（对比基线）→ 下一轮

**body 结构特征**：
- 审计 Skill 必须包含评分标准（A/B/C/D）和证据要求
- 必须输出量化基线（供后续评估对比）
- 评估 Skill 必须包含基线-目标-实际三值对比

---

## 模式五：一键启动模式

**描述**：从一份完整的简报出发，一键生成整套执行包（多个文档），压缩多步手动流程为一个 Skill 调用。

**适用场景**：
- 有标准化的执行流程
- 输入已标准化（如 Brief 模板）
- 输出固定为多个文档

**frontmatter 特征**：
- inputs：简报文档（必须已审批）
- outputs：多个文档的文件列表
- duration_estimate：通常较快（15-30 分钟）

**body 结构特征**：
- 必须包含前置条件检查（简报完整性验证）
- 每个 Step 对应一个输出文档
- 必须包含文档间的交叉一致性检查
- 总输出必须有汇总确认步骤

---

## 如何选择模式

| 你的新 Skill | 推荐模式 | 原因 |
|-------------|---------|------|
| 定义策略/框架/方向 | 策略-执行分离 | 策略独立，执行交给专门 Skill |
| 具体执行某个动作 | 策略-执行分离 | 从策略 Skill 获取输入，专注执行 |
| 项目型工作（有起止） | 简报-方案-复盘 | 覆盖完整生命周期 |
| 新平台/渠道的运营 | 平台-内容-运营三角 | 平台规范 + 内容规范 + 运营策略三者分离 |
| 诊断/评估/审计 | 审计-迭代 | 需要基线 → 改进 → 评估的循环 |
| 从简报快速生成多文档 | 一键启动 | 输入输出标准化，压缩流程 |
| 不确定 | 混合使用 | 新 Skill 可能融合多种模式 |

> BookForge Studios 系统在应用这些模式时，应参考系统既有的 Skill 分布（Phase 1 扫描结果），选择与系统风格一致的模式。
