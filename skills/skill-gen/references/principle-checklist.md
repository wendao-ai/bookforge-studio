# BookForge Studios 原则检查清单

skill-gen 在 Phase 5（验证）阶段使用此清单，逐项检查新生成的 Skill 是否符合 BookForge Studios 系统原则。

七维度结构：**前 4 维度通用**（任何 Studios 系统都需要），**后 3 维度参数化**（从设计文档核心理念提取，体现 BookForge Studios 的独特设计哲学）。

---

## 一、否定边界（通用维度）

每个 Skill 必须明确声明"不负责什么"，避免职责模糊和触发冲突。

| # | 检查项 | 检查方法 | 不通过处理 |
|---|--------|---------|-----------|
| N1 | Skill 是否明确声明了"不负责什么"？ | 检查 description 或运营规则中是否有否定边界 | 添加否定边界声明 |
| N2 | 否定边界中引用的 Skill 是否存在？ | 对照 .claude/skills/ 验证 | 修正引用或标记需创建 |
| N3 | 新 Skill 与现有 Skill 是否存在未被声明的职责重叠？ | 对比现有 Skill 的 description 和 outputs | 在否定边界中补充声明 |

---

## 二、Agent 协调（通用维度）

agents 字段中的角色必须真实存在、层级合理、协作关系清晰。

| # | 检查项 | 检查方法 | 不通过处理 |
|---|--------|---------|-----------|
| A1 | agents 字段是否遵循系统既有的 Agent 层级？ | 对照 .claude/agents/ 的 layer 字段 | 调整 Agent 列表 |
| A2 | agents 字段中的角色名是否都在 .claude/agents/ 中存在？ | 对照 Agent 目录验证 | 修正角色名或建议创建 Agent |
| A3 | 如涉及跨层协作，是否声明了协调机制？ | 检查是否有横向咨询说明 | 添加协调说明 |

---

## 三、质量门控（通用维度）

Quality Gates 必须存在、可量化、含不通过处理。

| # | 检查项 | 检查方法 | 不通过处理 |
|---|--------|---------|-----------|
| Q1 | 是否包含 Quality Gates 章节？ | 检查 body 结构 | 添加 Quality Gates |
| Q2 | Quality Gates 中的检查项是否可量化/可客观判断？ | 检查是否有"至少 X 条""必须包含 Y"等具体标准 | 重写为可量化的检查项 |
| Q3 | Quality Gates 中是否包含"不通过的处理"？ | 检查每项是否有对应的处理方式 | 添加不通过处理说明 |

---

## 四、系统一致性（通用维度）

术语、命名、路径在系统内必须一致，避免 skill 间出现同义词漂移。

| # | 检查项 | 检查方法 | 不通过处理 |
|---|--------|---------|-----------|
| S1 | Skill 使用的术语是否与系统术语表一致？ | 对照系统既有 Skill 的术语用法 | 统一为系统术语 |
| S2 | 文件输出路径是否遵循系统既有的目录约定？ | 对照 .claude/docs/ 或现有 Skill 的 outputs | 修正为系统约定路径 |
| S3 | Skill 命名（name 字段）是否符合系统命名风格？ | 对照现有 Skill 的命名模式 | 调整命名 |
| S4 | 系统核心术语参考：_（设计文档未提供术语表）_ | — | — |

---

## 五、人类驱动协作（BookForge Studios 特化维度）

关键创作决策（世界观、史观、人物命运、核心论点）由人类拍板，AI 提供选项与草案

| # | 检查项 | 检查方法 | 不通过处理 |
|---|--------|---------|-----------|
| P1 | Skill 是否体现了 人类驱动协作？ | 检查 body 内容是否包含与 人类驱动协作 相关的做法 | 补充相关内容 |
| P2 | 输出是否符合 人类驱动协作 的标准？ | 检查 Quality Gates 是否含相关检查项 | 添加对应检查项 |

---

## 六、协作协议（BookForge Studios 特化维度）

`Idea → 苏格拉底深挖 → 类型识别 → 大纲范式 → 扩展规划 → 分段写作 → 模拟审校 → 排版交付`

| # | 检查项 | 检查方法 | 不通过处理 |
|---|--------|---------|-----------|
| P1 | Skill 是否体现了 协作协议？ | 检查 body 内容是否包含与 协作协议 相关的做法 | 补充相关内容 |
| P2 | 输出是否符合 协作协议 的标准？ | 检查 Quality Gates 是否含相关检查项 | 添加对应检查项 |

---

## 七、统一底座 + 范式差异化（BookForge Studios 特化维度）

六阶段流水线是共享底座，每种类型在每个阶段都被其 Genre Pack 特化

| # | 检查项 | 检查方法 | 不通过处理 |
|---|--------|---------|-----------|
| P1 | Skill 是否体现了 统一底座 + 范式差异化？ | 检查 body 内容是否包含与 统一底座 + 范式差异化 相关的做法 | 补充相关内容 |
| P2 | 输出是否符合 统一底座 + 范式差异化 的标准？ | 检查 Quality Gates 是否含相关检查项 | 添加对应检查项 |

## 快速判定矩阵

按 Skill 的 category 决定哪些维度必须通过、哪些可豁免。通用维度（一/二/三/四）对所有 category 强制；特化维度按下方矩阵。

| category | 必须通过的特化维度 | 可豁免的特化维度 |
|----------|-------------------|-----------------|
| "drafting" | 五、六、七 | 无 |
| "extended-outline" | 五、六、七 | 无 |
| "genre-detection" | 五、六、七 | 无 |
| "ideation" | 五、六、七 | 无 |
| "outline" | 五、六、七 | 无 |
| "review" | 五、六、七 | 无 |
| "sedimentation" | 五、六、七 | 无 |
| "typeset" | 五、六、七 | 无 |

> 默认规则：未列入矩阵的 category，默认所有 7 维度都必须通过。系统级 Skill（category: "system"）可豁免所有特化维度。
