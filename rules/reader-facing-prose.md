# Reader-Facing Prose Rules（读者向正文纪律）

> 内化自 ai-tob-endgame v4 重构 dlg-035（2026-07-27）：V3 polish 漏审导致正文残留创作元叙事，用户抽查 ch01 发现"资料库里有素材…本章拎出来"出戏段落。本 rule 防复发。

## Mandatory Standards（critical）

正文是给读者的（公开出版），不是团队内部分享。以下内容**禁止出现在正文**：

### 1. 内部资料库/调研引用标注
- 禁止：`[资料库 13.6 §5.1]`、`[F8 §4.2]`、`（资料库 08.3 §4.2）`、`[F1-F10 ...]` 等内部篇目编号/调研文件引用
- 数据来源用读者可识别的形式：`据公开财报`、`McKinsey 2025 数据`、`智谱 IPO 招股书`、`公开报道`

### 2. 创作过程暴露
- 禁止：`资料库里有大量相关素材…本章把它们拎出来，叫XX`
- 禁止：`本书把它们提炼成/归纳为/整合成XX`（展开创作过程的版本）
- 禁止：`这是本书框架——资料库 09.3 和 10.2 有相关素材，但未把XX拆成…本书把它拎出来命名为XX`
- 禁止：`本章的 XX 定义来自…提炼，本书把它命名为XX`
- 概念归属用简洁读者视角：`本书称之为'三个原子约束'`、`本书合称为'四大死亡机制'`——一句话定义即可，不展开"怎么攒的素材"

### 3. 内部标识符
- 禁止：`（concepts.yaml c006）`、`（ta-02）`、`（理论锚 ta-03）` 等内部概念 ID / 理论锚编号
- 禁止：`F2 调研`、`F8 调研`、`F10 断层` 等内部调研文件名/断层编号
- 禁止：`rg-cXX`、`appr-XXX`、`dlg-XXX` 等内部流程编号

### 4. 过度章节预告
- 禁止：`后续所有章节（护城河、定价、交付、卖结果）都将回到这三个约束上来检验判断`（冗长章节清单预告）
- 改为：`这个框架贯穿全书。` 或直接删
- 保留：正常的简短章节交叉引用（`第五章会讲怎么建护城河`、`下一章看死亡名单`）——读者导航需要

## 判断边界

问自己：**这句话读者需要在书里读到吗？**

| 内容 | 读者需要？ | 处理 |
|---|---|---|
| `资料库 13.6 §5.1 说…` | 否（内部溯源） | 删/改为公开来源 |
| `本书称之为三个原子约束` | 是（概念定义） | 留 |
| `Cursor 在美国收 $20/月` | 是（案例数据） | 留 |
| `[资料库 13.6 §5.1]` | 否（内部标注） | 删 |
| `（concepts.yaml c006，ta-02）` | 否（内部 ID） | 删 |
| `第五章会讲护城河` | 是（读者导航） | 留 |

## 审核时机（防复发）

1. **V3 polish 必须执行元叙事清除**：`polish_chapters_v3.py` / `purge_meta_narrative.py` 的 prompt 含此检查清单
2. **review-chapter 把元叙事违规列为 critical**：一致性引擎拦截（`去厂商中心化` 同级）
3. **draft 阶段 prompt 边界**：V1 draft 允许"标注本书命名"，但必须用读者视角简洁表述（`本书称之为XX`），禁展开创作过程

## Anti-Patterns（典型违规）

- `[资料库 13.6 §5.1]` 出现在正文（暴露内部溯源）
- `本章把它们拎出来，叫XX`（暴露命名动作）
- `这是本书框架——资料库 09.3 有素材`（暴露创作幕后）
- `（concepts.yaml c006，理论锚 ta-02）`（暴露内部 ID）
- `F8 调研里最直接的证据`（暴露内部调研文件）
- `后续所有章节都将回到这三个约束上来检验判断`（冗长预告，出戏）

## 适用范围

- 所有 `drafts/chapters/*/v*_*.md` 正文
- 选题大纲.md / 全书_v*.md（读者可见产物）
- 不适用：dlg-log / brief / outline / registry / review 等内部创作文件（这些可保留内部标识符）
